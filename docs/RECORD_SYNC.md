# 기록 전송 신뢰성 보완 · v42

이전 수업의 개별 기기 로그가 없어 수분 지연의 유일한 원인을 확정하지 않는다. 코드에서 확인한 병목은 오래된 실패 기록에서 중단되는 직렬 재전송과, 각 학생이 접수·조회 때마다 시트 정리를 중복 호출하는 구조다.

- 미전송 큐는 최신 기록부터 처리하고, 한 기록이 실패해도 다른 기록을 계속 전달한다. 영구 거절은 기기에 남겨 ‘선생님 확인 필요’로 표시하고 자동 반복에서 제외한다. 수동 재전송으로 다시 확인할 수 있다.
- 기록 ID별 단일 전송을 유지하고 재시도 간격에 지터를 둔다. 최종 기록 전송 중에는 주기적인 수업/순위 조회를 중복하지 않는다. 복귀·연결 복구·주기 재시도를 유지한다.
- 서버가 접수한 뒤 응답만 유실된 경우 학생의 기록 조회에서 ID·횟수·측정시간·수업 ID를 대조해 도착을 확인한다. 서버 확인 없이 ‘도착 완료’라고 표시하지 않는다.
- 서버는 짧은 공유 임대를 통해 학생 한 명에게만 배치 정리를 위임한다. 학생마다 순위 조회에서 정리를 호출하지 않는다. 교사는 10초 간격 이하로만 정리를 재시도한다. 이미 영구 접수된 기록은 시트 정리 완료를 기다리지 않고 순위에 반영된다.
- 시트 정리 요청이 바쁘면 스프레드시트를 먼저 열지 않고 반환한다. 측정·전송 중 교사의 정기 전체 이력/시트 서식 조회를 줄인다.
- 학생 결과 화면에 기기 보관·전송 중·서버 도착 확인 및 ‘지금 다시 보내기’를 표시한다. 홈에는 미전송 수와 확인이 필요한 기록을 표시한다. 교사 차트는 측정 중·결과 수신 대기·기록 확정을 구분한다. 임시 결과를 최종 순위로 승격하지 않는다.

검증: 15개 독립 브라우저 저장소와 모의 서버에서 0회, 응답 유실, 모든 POST 응답 유실 후 조회 확인, 오래된 영구 거절, 일시 연결 실패, 자동 복구, 수동 재전송, 지연 학생 표시를 확인했다. 새 기록 15건을 중복 없이 수신했고 거절된 과거 기록은 기기에 남겼다. 테스트 중 배치 정리 요청은 총 4회였다. 이 수치는 모의 테스트 결과이며 실제 Apps Script·교실 네트워크 지연 측정치가 아니다.

기존 24시간 순위·성장왕·반별 노래·안무·카메라 로직과 디자인 가이드 MD는 보존한다. 실제 운영 학생 기록을 생성하는 부하 시험은 수행하지 않는다. Apps Script의 서비스/동시 실행 제한과 기기 연결 상태가 있어 하드 실시간 전달을 보장하지 않는다. 참고: https://developers.google.com/apps-script/guides/services/quotas 및 https://developers.google.com/apps-script/guides/support/best-practices
