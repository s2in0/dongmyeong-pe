# 줄넘기 기록 전송과 순위 · 2026-10-15

학생의 측정 완료 기록은 기록 ID별 Script Properties에 영구 접수한 뒤 성공을 응답합니다. 시트 전체 조회, 음악 제출 조회, 요약 시트 서식을 기다리지 않습니다. 선생님 순위와 기록 표는 별도 경량 요청으로 2초마다 접수된 기록과 시트 기록을 합쳐 확인합니다. 학생 결과 화면은 자신의 전송 완료를 먼저 표시하고 순위를 별도로 확인합니다.

시트에는 접수된 기록을 최대 60건씩 한 번에 씁니다. 시트 쓰기와 완료 확인에 성공하고 조회용 캐시를 공개한 뒤에만 접수 데이터를 지웁니다. 응답 유실이나 캐시 소실 시 원본과 기록 ID를 확인해 복구하며 같은 ID를 두 번 추가하지 않습니다. 학생 기기의 미전송함도 성공 응답 전에는 지우지 않습니다.

순위 캐시는 영구 원본으로 사용하지 않습니다. Google Cache Service는 조기에 사라질 수 있으므로 시트 및 영구 접수 데이터에서 다시 구성합니다. 캐시 항목은 40KB 정도로 나누고, 설정·순위의 공통 조회는 1초만 공유하며 새 설정 및 새 기록 접수 때 무효화합니다. [Google Cache 문서](https://developers.google.com/apps-script/reference/cache/cache)

접수 공간은 120건 및 전체 속성 약 440KB 이내로 제한합니다. 공간이 부족하면 성공을 응답하지 않고 학생 미전송함에 남겨 자동으로 다시 보냅니다. 7일이 지난 조회용 수업 메타데이터는 대기 기록이 없을 때 정리하며 수업이력 원본은 보존합니다. [Google 속성 서비스 한도](https://developers.google.com/apps-script/guides/services/quotas)

측정 시작 당시 수업 스냅샷으로 시간·재도전 횟수를 검증합니다. 선생님이 측정 도중 설정을 바꾸어도 완료 기록은 이전 수업의 기록으로 보존합니다. 서로 다른 시간이나 수업의 점수를 현재 순위에 섞지 않습니다. 최종 순위 발표 중에도 새로 도착한 기록을 반영합니다.

검증: `test_fast_records.cjs`, `test_record_delivery.mjs`에서 15건 시트 대기 없는 접수, 한 번의 일괄 쓰기, 0회 기록, 중복·재시도, 캐시 소실 복구, 이전 수업 기록, 학생 본인 기록 공개 범위, 교사 인증, 쓰기 응답 유실 복구를 확인했습니다. 15개 학생 화면과 선생님 화면의 모의 서버 테스트에서는 전체·음악 조회를 지연시켜도 약 2.1초 만에 15명 표시, 전송 응답 유실 복구, 최종 발표 중 추가 기록 반영, 오래된 조회 결과 무시를 확인했습니다. 실제 아이패드 동시 수업의 네트워크 속도를 보장하는 결과는 아닙니다.

측정 회차(sessionId)와 설정 스냅샷(lessonId)을 구분합니다. 활동 닫기·재도전·공개 범위·기록 방식 변경은 같은 회차를 유지합니다. 시간·준비 시간·감도 변경, 다른 날짜 또는 새 줄넘기 수업 시작은 새 회차를 만듭니다. 원본 기록 14열 뒤에 sessionId 열만 추가하며 이전 데이터는 보존합니다.
