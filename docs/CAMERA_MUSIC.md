# 카메라 연결과 노래에 맞춘 8박 동작

카메라 요청은 동작 인식 모델을 기다리지 않고 시작합니다. 미리보기 화면을 먼저 연결하고 인식 모델을 병행 준비합니다. 중복 연결 요청은 합치고, 취소·지연된 권한 응답의 미사용 스트림은 해제합니다. 연결 실패는 같은 화면에서 다시 시도할 수 있습니다. 웹앱은 Safari의 카메라 권한 설정을 임의로 변경하지 않습니다. [getUserMedia 문서](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)

MediaPipe Tasks Vision 1.0.1과 기존 pose lite 모델을 같은 사이트에서 제공하며 큰 카메라 자산은 별도 지속 캐시에 보관합니다. 앱 갱신 때마다 준비 파일 캐시를 비우지 않습니다. 인식 카운터 알고리즘은 변경하지 않았습니다. iPad는 CPU 경로를 사용해 GPU 초기화 실패 뒤 추가 대기를 피합니다. 모델과 SDK 출처 및 Apache 라이선스는 vendor/mediapipe에 있습니다.

음악 안무 한 칸은 8박, 한 줄은 8칸(64박)입니다. 학생이 BPM을 입력하며 추천 범위는 120~128, 기존 다른 BPM 입력도 유지합니다. 줄 추가·접기·복사·이동과 동작 편집을 유지합니다. 마지막에 노래 파일을 선택하고 재생하면 3초 카운트다운 뒤 노래와 강조가 함께 시작됩니다. Web Audio 시계를 기준으로 현재 동작을 계산하며 타이머 지연을 누적하지 않습니다. [WebKit 재생 정책](https://webkit.org/blog/6784/new-video-policies-for-ios/)

MP3/M4A/WAV, 최대 10MB 파일을 기기에 보관하고 제출 시 교사 Drive의 비공개 JUMPY 제출곡 폴더에 저장합니다. 파일 공유 링크를 만들지 않습니다. 교사 PIN 및 해당 반의 제출 ID를 확인한 뒤 노래를 읽습니다. 파일 형식·체크섬·크기 검증과 제출 ID 중복 확인을 적용합니다. 새 Drive 접근 권한은 배포 시 교사의 별도 승인이 필요합니다. 각 반은 하루 최대 60건·150MB 이내로 음악 제출을 받습니다. 음악 작업은 줄넘기 즉시 접수 및 경량 순위 조회와 분리됩니다.

구버전 제출은 한 칸 1박으로 보존합니다. 새 초안은 한 칸 8박이며 기존 초안 전환 전 로컬 백업을 남깁니다. 음악 원본 첫 14열 뒤에 노래 메타데이터와 동작 박자 수를 추가합니다. 기존 원본 및 두 디자인 가이드 MD를 수정하지 않습니다.

검증: 카메라 시작 우선순위·늦은 권한 응답·취소 정리·중복 요청 단위 테스트 통과. 실제 로컬 SDK/WASM/모델 준비를 Chromium에서 확인했으며 카메라 권한은 요청하지 않았습니다. 노래가 있는 모의 화면에서 3·2·1, 8박 유지, 8칸 한 줄, 강조, 취소, 제출 및 교사 재생 로드를 확인했습니다. 실제 iPad 카메라 연결 시간 및 Safari 권한 동작은 별도 현장 확인이 필요합니다.
