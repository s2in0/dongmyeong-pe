# 줄넘기 인식·순위 v43 보완 검증 (웹 캐시 v44) (2026-10-22)

## 바뀐 판정

기존 몸통 판정에 바닥에 가까운 발의 상승 신호를 보조로 추가했다. 양발 높이의 평균은 번갈아뛰기에서 상쇄될 수 있다. 보조 신호는 발목·발뒤꿈치·발끝 중 보이는 점으로 만들고, 움직임이 반대인 두 발 중 바닥 쪽 발의 높이를 사용한다. 몸통이 작게 움직이는 빠른 점프를 확인할 수 있다.

각 채널은 실제 상승·하강과 3회의 리듬을 먼저 확인한다. 빠른 주기가 확인되면 몸통 높이 문턱·평활화·최소 간격을 조절한다. 보조 발 판정은 짧은 주기에서만 사용하고, 몸통과 발이 본 같은 점프는 두 신호 중 더 빠르게 실제 확인된 주기에 맞춰 합친다. 몸통 신호가 격회로만 보이는 경우에도 실제 관찰된 발 상승을 함께 버리지 않게 한다. 보이지 않는 점프를 박자로 추정해 더하거나, 번갈아뛰기를 무조건 두 배로 계산하지 않는다. 화면 밖 발·걷기·어깨 흔들기·무릎만 들기·카메라 중단 검사를 유지한다. 실제 발의 일시적인 신뢰도 저하가 전체 프레임을 버리지 않게 발의 최소 가시성은 몸통과 따로 적용한다.

[참고 프로젝트의 실제 노트북](https://github.com/AyushTCD/VisionBasedJumpRopeCounter/blob/main/FinalScript.ipynb)은 엉덩이 높이의 국소 극값과 무릎 각도를 사용하고 배경 차분으로 줄 영역을 확인한다. 전체 영상 이력을 반복 계산하는 코드를 복사하지 않고, 웹에서 매 프레임 처리하는 수업용 판정을 구현했다. 해당 프로젝트가 주장하는 정확도를 점피의 정확도로 인용하지 않는다.

## 실제 영상 검사

유튜브 원본 8개 구간에 대해 브라우저의 실제 MediaPipe lite / Tasks 1.0.1 CPU 추론을 **22회 완료**했다. 번갈아뛰기 구간은 원본 프레임과 15·20 FPS 표본으로 모델을 새로 만들어 반복했다. 정확히 디코딩한 원본 프레임을 최대 긴 변 720픽셀로 입력했고, 그 좌표를 동일한 기존(v42)·수정(v43) 웹 카운터에 넣었다. 추출 중 발생한 이미지 읽기 오류는 해당 실행을 실패로 처리하고 다시 실행했다.

[전체 구간·출처·프레임 수·기존/수정 횟수](COUNTER_V43_RESULTS.json)에 모든 완료 실행과 실패가 남은 사례를 포함했다. `referenceCount`가 null인 구간은 재현·안정성 검사이며, 수동 정답이 검증된 정확도 표본으로 취급하지 않는다. 횟수가 늘었다는 사실만으로 정확도가 올랐다고 판정하지 않는다.

카메라를 정면에 고정하고 머리부터 양발까지 보이게 안내한다. **아주 빠른 동작·측면·가림·낮은 프레임 수에서는 여전히 누락할 수 있다.** 실제 선생님/학생 아이패드 촬영본은 이번 검사에 없으므로 수업 전 정면에서 직접 센 20회를 빠른 두발·번갈아뛰기 각각 비교해야 한다. 모든 구간에서 인식 문제가 완전히 해결됐다고 주장하지 않는다.

## 전송 검사

15개의 독립 학생 브라우저 저장소에서 동시에 최종 기록을 제출하는 모의 검사를 통과했다. 0회, 응답 유실, 동일 ID 재전송, 오래된 거절 기록, 네트워크 끊김 후 자동/수동 복구, POST 응답이 모두 유실된 뒤 서버 조회로 접수 확인하는 경우를 검사했다. 15개 고유 기록 모두 접수됐고 느린 학생 한 명은 확정 기록과 분리해 전송 대기로 표시했다. Apps Script 서비스 모의 검사도 15개 기록의 빠른 접수·즉시 순위 반영·중복 방지·단일 시트 일괄 저장을 통과했다.

실제 운영 서버에는 원본 학생 기록을 오염시키는 가짜 기록을 제출하지 않았다. 대신 시트를 읽거나 쓰지 않는 ping 15개를 동시에 보내 **15/15 응답, 1.720–2.057초**를 확인했다. 이는 접속 응답 시간이며 기록 저장과 교사 화면 표시까지의 시간을 뜻하지 않는다. 학교 와이파이와 실제 아이패드 15대의 종단 간 지연은 아직 측정하지 않았다. 기존 최종 기록 우선 전송·기기 보관·재시도·서버 접수 확인 방식을 유지했다.

## 순위와 게시

실시간 횟수 → 전원 제출 또는 교사 종료 시 오늘 기록 → 버튼으로 오늘 이전 같은 시간의 최고기록 대비 향상 순위. 공동 순위·첫 기록·0회·감소·날짜 경계와 교사 종료 뒤 진행 중 학생의 분리를 모의 화면에서 확인했다. 자세한 규칙은 [순위 설명](GROWTH_RANKING.md)에 있다.

새 서버 코드나 스프레드시트 변경은 없다. Apps Script v19를 그대로 사용하며 웹 캐시 v44로 게시한다. 음악 파일·학생 원본 기록·디자인 가이드 MD는 수정하지 않았다.
